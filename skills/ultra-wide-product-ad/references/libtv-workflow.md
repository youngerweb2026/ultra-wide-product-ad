# LibTV 执行与恢复

宿主负责分析、文案、分镜和最终提示词；LibTV 执行已确认请求。使用当前工具的工作流摘要和 schema，不另启动 Canvas Agent 或其它创作模板重写用户方案。仅开发 Skill 或只交付提示词时不操作画布。

## 准备期：在最终确认前核对模型和费用

1. 只要求 Skill 开发或提示词时，不必调用远端，拟用参数明确标为未核实。正式成片任务先用 `doctor` 检查连接与账号身份，遵循当前工作流路由建立必要上下文。继续已有项目时读取精确画布 UUID，不能用数字项目 ID 或仅凭重名画布匹配；必要时用 `target_project` 建立上下文。
2. 在视频工作流内用 `search_models` 查 Minimax H3，再以返回的完整 `modelName` 调 `get_model`。读取参考模式、时长、画幅、清晰度、数量、提示词长度与声音能力，先据此编写最终可执行提示词。模型查询不需要先上传产品图；不要等提示词确认后才发现常规参数不兼容。禁止把历史参数枚举或价格当成当前事实。
3. 按预计使用的一张产品图选择实际支持的参考模式。所需 3:4、10 秒、768P 必须在该模式内有效，不能套另一模式的参数。不要默认把产品图强制作为视频第一帧，以免开头变成完整静态产品；若实际只能首帧绑定，提前说明对贴面开场的影响并提出可审查方案。
4. 有可靠报价则展示；无法取得报价时，明确披露“点数尚未核实”，并把确认范围写成按平台实际价格执行指定模型、规格、时长、数量的一次任务，不含额外重试。只有用户同意这一范围才执行；用户另设金额或点数上限时，必须先核实不会超限。查询模型与准备参数本身不等于生成授权。

## 确认后：绑定图像和预检

1. 本次产品和实际生成包已获确认后，复用合适画布或创建本次制作项目；核对精确 UUID，用 `target_project` 建立上下文。准备期已建立正确上下文则沿用，不重复创建。
2. 若需要操作浏览器，使用 Google Chrome。不要依赖自动打开到系统默认浏览器；在支持时设 `openInBrowser:false`，需要看画布再用 Chrome 打开真实交接链接。
3. 原图通过 `upload_ticket → 按返回签名信息上传 → upload_complete` 上传。按实时接口创建或取得可用图像节点，回读其类型、资源 URL、尺寸与产品内容。上传完成不自动证明图像节点已连接；不要猜节点 ID、assetId 或资源路径。
4. 以真实引用预检准备期已选模式。可用 `mode:"auto"`，但必须检查解析结果符合已确认模式和参数；必要时显式选择预检支持的模式。已有明确完整授权就沿用，不重复询问相同内容。

## 预检与提交

用真实项目、图像节点、完整提示词和已核对参数调用 `validate_generation_plan`。它的通过结果验证可提交性，不证明画面质量。失败时先修复引用或参数映射；如果需改提示词、文案、模型、画幅或超出已授权费用范围，展示变化后再确认。已授权按平台实际价格执行这一特定任务时，查到报价本身不构成新增范围；用户另设的费用上限仍然有效。

当前 typed 工具的核心映射如下，执行时仍以工具现场 schema 为准：

| 字段 | 内容 |
| --- | --- |
| `projectId` | 精确画布 UUID |
| `model` | 实时发现的完整模型展示名，不能传自编名称 |
| `mode` | 可用且预检通过的参考模式 |
| `name` | 当前产品的广告任务名 |
| `prompt` | 已展示、已保存、已确认的实际文本 |
| `referenceImageNodes` | 上传原图对应的真实 image 节点 ID |
| `params` | 按当前模型 schema 映射的时长、画幅、分辨率等；默认一次约10秒、1条 |
| `idempotencyKey` | 本次提交的稳定唯一身份，同一未知请求恢复时不换新值 |
| `run` | `true` 才实际生成；`false` 会创建或预检节点，不属于已生成视频 |

`validate_generation_plan` 不带 `run` 或 `idempotencyKey`；生成时用支持这些字段的 `generate_video`。模型、模式、提示词、媒体列表由工具顶层管理，不塞进 `params` 覆盖；`count` 等仅在真实 schema 支持时传入。不编造 `audio=false` 等开关，音效文本要求也不保证实际有音轨。

默认使用 `generate_video` 提交一个整片任务，包含七镜时间轴和转场。保存实际请求及原图内容指纹，生成中不改提示词、不重复提交。

## 等待和恢复

- 当前 `generate_video` 工作流默认在同一次调用内等待结果。调用未返回时，不额外查 `task_status` 或再调生成工具；若外层 `functions.exec` yield，只用 `functions.wait` 恢复原 cell，直到它真正结束。遵守工具当时的等待与进度输出规定。
- 只有原调用已经结束且返回需要恢复的任务身份，才用同一 `project_id`、`task_id` 回读 `task_status`。其它明确异步提交工具按自己的 schema 恢复，不混用不同命名风格的参数。
- 超时或断线先定位原任务，查已存在的节点、资源和任务状态；未知成功与否时不换幂等键重投。终态失败后也不自动获得新付费尝试额度。
- 完成后回读实际媒体资源、时长、画幅、音轨和可下载地址。画布节点、模型自述、成功通知都不能替代真实视频。

## 输出与记录

仅整片生成无需为交付强造时间线；下载生成原片并验收即可。确有剪辑或导出需求时，按实时 `export_readiness → export_video → export_status` 或已说明的本地处理路径执行，检查实际文件而非只看导出状态。

在当前项目内保存简洁任务记录，至少包含：产品图及其指纹、精确文案、实际提示词文件、用户确认范围、模型与真实参数、项目/节点/任务身份、幂等键、生成原片位置、最终片位置、验收结论。可用一个 JSON 或 Markdown 文件，不要求一套复杂审批档案。URL 中的临时签名、上传凭据和账号秘密不进入可分享的交付文件。

额外重试、分段修复、换模型或大幅提高规格需在已有授权范围内；范围外先展示具体变更和新增次数。用户只授权一次时，候选片不达标也应交付实情与下一步，不能自行无限重生成。
